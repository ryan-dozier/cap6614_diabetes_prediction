# R05 related work on target adaptation and artifact mitigation

Reviewed and approved by Ryan Dozier on November 3, 2026. Reconciled November 9, 2026. This focused review supports the choice of an R06 intervention and complements the [implemented-model comparison](r05_model_comparison.md) and [research questions](research_questions.md).

## Research question and scope

The project uses two already available synthetic diabetes tables and evaluates transfer to NHANES. The operational question is whether either synthetic source adds predictive value when only a small number of NHANES diagnoses are available, and whether a selection rule can reduce negative transfer. Keep three uses of synthetic data separate when comparing studies: foundation-model pretraining across tasks, generating new examples from a target training partition, and adapting a downstream predictor with an existing synthetic table. Each gives the method different access to the target distribution.

## Synthesis and proposed contribution

The closest augmentation studies ask whether a generator trained on available real data produces useful extra examples. Here the synthetic rows already exist and were sourced separately from NHANES. The real-only baseline answers whether those rows help beyond the same limited real supervision. A synthetic-only baseline answers how well the source transfers without NHANES labels. Comparing both synthetic sources reveals whether conclusions depend on which table supplies the extra examples.

Retrieval and fine-tuning studies show that the choice of labeled context and the choice to update weights are distinct interventions. The implemented adapters already support changing context while keeping weights frozen. This makes fixed-context composition the simpler first adaptation experiment. A query-specific retrieval experiment would require additional implementation and a random context control of the same size and domain composition.

The literature establishes precedents for augmentation, context selection, importance weighting, and removal with retraining. The proposed contribution is a controlled comparison of how two separately sourced synthetic tables support a common NHANES prediction task under explicit label budgets, followed by a targeted test of whether domain-informed feature removal helps. This is a proposed empirical contribution. The targeted search does not establish priority for that exact comparison or selection rule.

## Candidate A: fixed-budget synthetic augmentation

**Question.** At a fixed number of labeled NHANES training participants, does adding examples from either synthetic source improve held-out NHANES prediction relative to the same real examples alone?

Use the same sampled NHANES participants across eligible conditions at each budget and seed. Treat the zero-label condition as synthetic-only. For positive budgets, compare real-only, synthetic-only, and mixed conditions for each synthetic source. For a fixed total context size, compare a mixed context containing b real examples plus N minus b synthetic examples with an N-row synthetic-only context. This contrast estimates the effect of replacing synthetic rows with real rows. The comparison of mixed against b-row real-only estimates the effect of adding synthetic rows to the available real examples. Those contrasts answer different questions and should be reported separately.

Keep the harmonized features, held-out participants, preprocessing rules, and applicable model settings aligned. Repeat the participant draws and pair comparisons within each draw. Specify how class support is handled for tiny budgets before running experiments. A one-row real-only sample cannot contain both classes, so record that condition as inapplicable for classifiers requiring both classes. Count all target labels used for fitting, early stopping, tuning, or calibration. Use the same frozen checkpoints for context comparisons. Define the task-trained model selection policy in advance so it does not create an uncounted validation-label budget.

Report paired changes in ROC-AUC with AP, Brier score, and log loss as secondary measures. A change in ranking and a change in probability quality can point in different directions. If gains differ between the synthetic sources, describe the interaction as an observed difference between those sources under the tested settings.

## Candidate B: domain-informed feature removal

**Question.** Does removing features that distinguish synthetic source rows from NHANES rows improve transfer compared with removing the same number of features by other rules?

Fit the domain diagnostic on source and NHANES development features. Estimate feature importance on held-out development data and predefine how correlated features and tied ranks are handled. Treat use of unlabeled NHANES development features as target access and disclose it separately from the label budget. Use a predeclared removal count or a small predeclared grid. Exclude held-out test participants from ranking and selection.

Compare all features, the domain-ranked removal rule, repeated random removal of the same number of features, and a source-predictive feature-selection baseline that retains the same number of features. Refit task-trained models and rebuild foundation-model contexts using the retained columns. Use the same rows, target label budget, and evaluation cohort across feature conditions. A drop in domain classifier accuracy is a diagnostic outcome. Improvement in held-out diabetes prediction is the intervention outcome. Compare both because removing a domain-distinguishing feature can discard valid predictive information.

A positive result would support the tested removal rule under the chosen source, model, and cohort. A negative result would help distinguish detectable shift from shift that the removal policy can mitigate. To keep the design feasible, test the rule first at a fixed label budget and use the broader budget curve only if that comparison is part of the agreed protocol.

## Decision for R06

Candidate A is the primary experiment in this draft because it directly tests the project’s practical question and can use the existing frozen models. Candidate B is the proposed mitigation experiment because the all-feature, matched-random, and source-predictive controls make the contribution of the ranking rule testable. Finalize budgets, repetition, selection rules, and uncertainty reporting in X01 and E05 before running the comparison.

The draft uses a targeted set of primary papers. The supplied ReTabSyn v2 and Localized TabICLv2 v1 protocols informed the reviewed related-work draft. ReTabSyn subgroup splits are distribution-shift experiments, not proof of pure covariate shift; Localized TabICLv2 weight updates use synthetic tasks, not target-domain fine-tuning. Existing NHANES test results are exploratory evidence for designing the study. Reusing the same participants on Newton does not make those results independently confirmatory.
